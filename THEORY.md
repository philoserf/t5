# A theory of `t5`

_A Naur-style account of the understanding needed to modify this system without
damaging its conceptual integrity. Addressed to whoever inherits it next._

## What the system is for

This is not a game engine, and reading it as one will mislead you at every turn.
It is a **transcription of three printed rulebooks into executable form**, and the
criterion of correctness is fidelity to a printed page — not plausibility, not
balance, not simulation quality. When the code and your intuition disagree, the
book wins. When the code and the book disagree, that is a bug no matter how
sensible the code looks.

The most consequential fact about this repository is that **the specification is
not in it**. `docs/pdf/` is gitignored, the extracted text under `docs/reference/`
is gitignored derived output, and both are copyrighted material each user supplies
for themselves. You have inherited an implementation of a spec you cannot diff
against, written by someone who could. This inverts the normal relationship
between code and comments. Here the doc comments are not explanation of the code —
they are the only durable record of what the source text says, including the parts
it says badly. Deleting a comment in this repo destroys information that exists
nowhere else in it.

The domain nests in five tiers: dice resolve tasks; tasks resolve worlds,
characters, and fights; worlds compose into star systems; systems into surveyed
sectors; characters crew ships, and ships fight and trade. The domain's native
output is a **compact code-string** — `A788899-C` for a world, `S-AL22` for a ship,
`8-De Hi In Na Po Cr1,800` for a cargo, and the full survey line
`A788899-C Ph Pa Ri {+4}(D7E+4)[9C6D] BcCeF NS -`. Treat these as the product
rather than as serialization of some richer inner model. A `uwp.Profile` exists to
render that string correctly; that is its job.

Two vocabulary traps will catch you early. `Size` names three unrelated things — an
eHex integer on a world profile, a luminosity class _string_ (`"V"`, `"III"`, `"D"`)
on a star, and a different eHex range on a gas giant. And a hull letter in `shipgen`
is an **ordinal** (`A` = 1 = 100 tons), not its eHex value (`A` = 10), in a codebase
where every other letter is eHex.

## The organizing ideas

**The dice stream is a hidden global interface, and its consumption _count_ is part
of the contract.** This is the deepest, least obvious, and most load-bearing
invariant in the system, and most of the surprising code descends from it. A sector
is generated by drawing from one `Roller` in sequence, so if a belt world spends
fewer dice than a solid world, every subsequent world in that sector changes. The
repo therefore tests not only what the dice produce but how many are drawn:
`worldgen/chartinvariants_test.go:135` asserts `typeSize(Planetoids)` spends exactly
zero dice, and `world_test.go:30` runs two identically-seeded rollers down the belt
and normal paths and compares the _next_ die. `dice.NewScripted` is exact rather
than cyclic and panics when outrun, precisely so a change in draw count fails loudly
instead of being served recycled faces. In `chargen` the same idea shapes the
design: Reward is rolled every term and discarded on death rather than skipped,
auto-benefits are applied after all rolled awards so they "cannot shift a single
die," `selectBranch` validates its policy index before the Soc roll so a bad policy
fails without first perturbing the stream, and `DefaultPolicy.RerollBranch` returns
false because keeping a branch rolls nothing.

If you take one thing from this document: **any change to how many dice a path draws
is a breaking change**, even when it cannot alter a single outcome.

**Package boundaries follow the rulebook's chapter boundaries, not software
concerns.** This is the vocabulary you most need and are least likely to guess.
`dice` and `task` are split _jurisdictionally_: page 127 states the Spectacular rule
about **tasks**, and pages 120–131 belong to `task`, so `dice` observes (counts ones
and sixes) and `task` acts (overrides Success). The argument is territorial, not
architectural. `internal/personals` goes further and documents a **citation rule** —
the chapter states every rule twice, as prose on pp.181–183 and as numbers on p.184,
so a named concept cites the prose page and a value table cites the table page.
Citations to an absent source are a governed, first-class artifact here.

**Comments record the losing evidence.** Because the book contradicts itself and the
spec is unavailable, the only defense against endless re-litigation is documenting
the rejected reading in full. The canonical case is the drive-cost ruling: modified
drive stages cost /2, not ×1. `drive.go:188` records that /2 appears on four pages
and ×1 on two, then quotes the losing side's worked example verbatim — p.48 walking
a fusion plant from 104t/MCr104 to 52t/MCr52 in prose. That quotation is there
because omitting it is how the cell was mis-resolved twice. The root `CLAUDE.md`
promotes four such decisions to a "Settled rulings — do not re-open" list. Treat
that list as load-bearing code.

**Strict on generator paths, total on display paths.** `ehex.Digit` panics out of
range while `ehex.Format` returns `"?"`; `task.Difficulty.Dice()` panics off-ladder
while `String()` returns `"?"`; `chargen.Character.Score` panics while `UPP()`
renders. Generators are trusted callers and a bad value there is a programming
error — but exported model types have public fields a caller may set directly, and a
`String` method must never crash. `uwp.formatStarport` exists so a zero-value
profile cannot emit a NUL into a piped record stream.

**Infeasibility is data, not control flow.** `shipgen`'s design functions return a
value plus `Problems []string`; clamps are always paired with a complaint so a
substitution is never silent. The one principled exception is stated at
`generate.go:44`: `Design` must never quietly build something other than what a naval
architect asked for, "but `Generate`'s 'request' is its own dice, and there is no one
to surprise."

**Fail-open assertions are the named signature defect.** This repo has repeatedly
shipped checks that pass when the mechanism they test is absent.
`clitest.AssertReportedSeed` therefore runs two stdout leak checks — an anchored
seed-line matcher derived from `cli.seedNote`, plus a broad `"seed"` substring —
because they fail in opposite directions and neither subsumes the other; collapsing
them looks like a tidy-up and already shipped once as a coverage regression.
`AssertRejected` separately greps for `panic:`, because an unrecovered panic
satisfies every other clause of "rejected cleanly."

**The pure-function pattern is real but narrower than advertised.** The docs claim
rule formulas are pure functions taking their rolls as arguments, with `Generate`
composing them in checklist order. That holds for the six mainworld characteristics
and their `systemgen` analogues, and essentially nowhere else. The Extensions layer
inlines every formula, and `RollEconomic` even varies its _dice count_ by population.
`placeOrbits` is 216 lines of rolling interleaved with placement under three
suppressed linters. The non-mainworld path substitutes a different and better-tested
discipline — Size hoisted above the type switch, every profile funnelled through
`chartProfile`, invariants asserted across all nine world types — but that is not the
shape the docs promise. A maintainer who trusts the advertised shape will go looking
for a pure function to edge-test and not find one.

## The seams

**The CLI contract is the best-defended boundary in the system, and it is genuinely
principled.** Records go to stdout, everything else to stderr, bad input exits 2.
Every run is reproducible: `cli.Roller` draws its own seed and reports it, so a good
run can always be replayed. The report is _deferred_ — `Roller` returns a
`reportSeed` func the caller invokes only after its own flags validate — because
`Roller` merely parses, and naming a seed before validation announced a seed for
records that were never generated. `RejectUnusable` treats a flag the chosen path
cannot honor as bad input rather than a no-op, asks `flag.Visit` rather than
comparing against defaults (because `-tl 0` is a real Tech Level), and exempts bools
explicitly set false because `-sector=false` is agreement, not conflict.

**The generator spine is connected; a second tier is not.** The dependency graph is a
clean DAG with no cycles — `sectorgen` imports only `dice` and knows nothing of
worlds, `route` defines its own minimal `World{Hex, Importance}` rather than
importing `worldgen`, and `survey` is the sole join point. Six CLIs drive that spine.
But `trade`, `shipcombat`, `combat`, `senses`, `personals`, and `calendar` have
**zero consumers anywhere in the repo**, reachable only from their own tests.
`shipcombat` genuinely bridges to `shipgen` — `HullLocations` is keyed on the same
hull ordinal a designed hull already carries, and the comment notes "nobody had ever
connected them" — so a designed ship _can_ fight. Nothing drives it. The distinction
that matters: `shipcombat`, `combat`, `senses`, and `personals` each have open
deferral-labelled issues, so they are parked with a planned tail. **`trade` has
neither an issue nor a consumer.** It is the one genuinely orphaned package, and at
96.2% it is also the best-covered — coverage here measures the library, not the
integration, and there is no integration.

**`trade`'s interface rejects the repo's own types.** It takes `[]string` trade codes,
`int` tech levels, and a `byte` starport, while `worldgen.World` already carries every
one of those inputs. There is no shared trade-code type or constant set anywhere; the
two-letter codes are bare literals scattered across both packages (`"Ri"` appears 51
times). A typo matches nothing, silently — the repo's own signature defect at an
unguarded boundary. This is latent rather than live, because nothing calls it.

**What is live is the belt contradiction, and it is the sharpest lesson in the repo.**
The settled ruling says: ask `Profile.IsBelt`, never compare Size to 0. But `IsBelt`
_is_ `p.Size == BeltSize`. **It is a rename of the forbidden comparison, not a
resolution of it.** A maintainer who follows the ruling to the letter gets the same
wrong answer with better-looking code and believes they have complied. `systemgen`
has already worked out the correct theory and states it at `satellites.go:190`: a
secondary world's belt-ness is its **type**, not its Size — `Planetoids` is the belt,
a Size-0 `Worldlet` is a very small world — which is why `satelliteBody` takes
belt-ness as an explicit parameter, because the caller's context decides it.
`worldgen` holds the opposite theory: `tcRules` stamps the asteroid code `As` on any
Size-0/Atm-0/Hyd-0 profile. The two disagree, and the disagreement reaches stdout:

```
7: Worldlet Y000233-A As Va Lo (3 moons: Ell Y575030-6; Ess HFFA669-9; Arr Y410041-6)
```

An asteroid belt with three moons — five such lines in 40 systems on one seed
(`go run ./cmd/systemgen -n 40 -seed 5`). This is the same shape as the bug the ruling
was written to prevent, surviving because the ruling names the wrong invariant.
`uwp.IsBelt` also has zero coverage from `uwp`'s own tests: the most re-litigated
invariant in the codebase is exercised only incidentally from downstream.

**The survey record is delimiter-recoverable, not positional.** The comment at
`world.go:161` argues that every empty field must be dashed rather than dropped
because the record is positional — true in spirit, and the bug it describes is real.
But the trade-code and stellar fields are both multi-token, so whitespace field
indices already shift. The dash rule preserves "no field is invisible," which is
weaker than "field _n_ is always field _n_," and the comment invites the stronger
reading. Relatedly, `Nobility` sits between two `dashIfEmpty` calls without one, and
`System.SecondSurvey`'s `name` argument is unvalidated while `allegiance` and `hex`
are both explicitly defended.

## What changes easily, and what does not

Adding a **career** is the best-supported change in the system: declare the data —
qualification, controlling characteristics, skill grid, muster table, rank ladders —
in its own file and hand-trace a golden with scripted dice. Adding a **weapon,
defense, trade good, or world characteristic formula** is a data edit plus a catalog
row. Adding a **CLI flag** is well-scaffolded.

Three kinds of change require rethinking something fundamental. **Anything that
shifts dice consumption** invalidates every golden script in the affected package;
those must be rewritten deliberately, not patched until green. **Making a sophont a
first-class character** means putting `Species` onto `Character` and touching the UPP
renderer, `Check`, and the career engine together — today slot 5 is hardcoded as
`Social` even for species whose sixth characteristic is something else, so the
non-lossy renderer lives outside the package in `cmd/sophont`, and `Character.Check`'s
documented variable-dice rule is contradicted by all ten of its call sites passing a
literal `2`. **Adding a fourteenth career _shape_** (as opposed to a fourteenth
career) runs into eleven boolean fields on `Career` that are dispatch switches read by
an `if` chain already carrying `//nolint:cyclop`. Career rewards and tables are data;
career term _shape_ is code selected by a flag stored in data.

A maintainer who lacks this theory will most likely cause damage in one of five
places, four of which have already happened. They will delete the "duplicate" second
cost table in `shipgen` — `stageData` and `stageCostData` deliberately reach the same
answer through independent evidence, so a correction to one must not silently move
the other. They will collapse `clitest`'s two stdout checks into the anchored one.
They will regenerate a seeded sample without checking the README. They will re-open
the drive-cost ruling — and there is a specific trap waiting: `drive_test.go:221`
closes with "Tracked in #300. Until it is settled, asserting either value here would
dress a coin-flip as a golden," which is pre-ruling residue that **directly
contradicts its own comment block's body**, sitting immediately above the assertion
it would license deleting. Fix that line first. And fifth, they will follow the belt
ruling as written and reproduce the bug it was meant to prevent.

The highest-value change available right now is fixing the `As` rule to consult
secondary-world type rather than Size, paired with a `worldgen`-local test asserting
what trade codes a Size-0 Worldlet carries — the absence of exactly that test is why
the contradiction survived.

## Uncertainties

I am inferring intent from code in several places and could be wrong.

**Verification effort here is allocated by dice-proximity, not by risk**, and I cannot
tell whether that is deliberate. Rolled paths are locked cell by cell; the
lookup-and-parse layer that actually touches user input is the least verified code in
the repo. `WeaponByName`, `MountByCode`, and `DefenseByName` are how `cmd/shipgen`
parses flags and are effectively untested — a hyphen-handling bug lived exactly there.
`NobleTitle` is called from `cmd/chargen` but its six title strings are pinned by no
test. One caution learned the hard way: I initially read `CareerByName`'s 0% as a gap
and was wrong — it _is_ exercised end-to-end by the CLI test table, and that zero is a
per-package attribution artifact. Check for cross-package coverage before trusting a
zero.

**The README's pinned samples have already drifted**, and the stated explanation for
how that happens is too narrow. I regenerated all four: worldgen, sectorgen, and
shipgen match byte for byte, but the chargen sample says `age 22` where the code emits
`age 27`, with every other field identical. `CLAUDE.md` frames this hazard as a
dice-stream shift falsifying the README. This drift was _not_ a stream shift — the
stream is provably unchanged — it came from a semantic fix to aging. The guidance
should be "regenerate whenever generator behavior changes," not only when draw order
does.

**The documentation layer is mid-refactor and uncommitted.** The working tree cuts the
root `CLAUDE.md` by 206 lines and redistributes it into nine new per-package files,
none of them tracked. Anyone cloning from origin today gets the old monolithic version
and none of the per-package theory. I cannot tell whether this is paused for review or
simply unfinished, but it is the first thing I would resolve, since those nine files
are where the settled rulings' full reasoning now lives. The workspace-level `NEXT.md`
row is separately stale, still naming work that shipped several waves ago.

**Two rolling idioms in `chargen` diverge for no stated reason.** Variant terms route
through `Character.Check` → `task.ResolveDice` and receive the Spectacular override;
standard Risk and Reward calls `dice.Resolve` directly and does not. The divergence is
inert today only because both roll 2D and Spectacular requires three dice. Given how
carefully this codebase argues its other jurisdictional splits, the silence reads more
like drift than intent — but I would ask before "fixing" it, because in this repo an
undocumented asymmetry is as likely to be a book faithfully transcribed as a mistake.
That ambiguity is the permanent condition of working here, and it is why the comments
matter more than the code.
